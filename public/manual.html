Freelancer System Editor — Manual

This manual walks you through the editor by doing real jobs: building a system, adding a base, reworking a defence grid, writing a side mission and shipping the result to players. Every screenshot is from the editor itself, running on the vanilla game.

For a complete list of what every panel, dialog and menu entry does, see the reference guide (F1 in the editor). This manual is the “how do I…” companion to it.

Getting started

Two ways to run it

In VS CodeInstall freelancer-system-editor-1.17.0.vsix (Extensions → ⋯ → Install from VSIX…), then run Freelancer: Open System Editor from the command palette. The editor opens in a tab; right-click a system .ini and choose Open in Freelancer System Editor to jump straight to it.
In a browserDouble-click start.bat in the editor folder. It starts a small local server and opens the editor in your browser. Close that window to stop it.

Choose your game folder

  1. The editor looks for Freelancer HD Edition next to its own folder. If it finds no game, the Freelancer game folder dialog opens; otherwise use File → Game folder….
  2. Click Browse… and pick the folder that contains DATA and EXE. Picking DATA or EXE itself works too; the editor moves up to the game folder. The dialog tells you straight away whether Freelancer was found there.
  3. Click Use this folder. In VS Code the choice is remembered in the extension settings.
Keep one folder per mod (for example a vanilla copy and a Discovery copy) and switch with File → Game folder…. The editor never touches anything outside the folder you chose.

The screen

  • Outliner (left): every object, zone and light in the open system. Search box on top, Objects / Zones / Lights chips to filter, ⚙ for more filters. The Systems tab switches between systems.
  • 3D view (centre): the system as the game builds it — models, zones, trade lanes, patrol paths, asteroid fields and nebulae. The Universe map tab shows the whole sector.
  • Toolbar (above the 3D view): Select / Move / Rotate gizmo, World or Local axes, Snap, 3D or Top view, Frame, and the View preset.
  • Properties (right): what you selected — position, rotation, archetype, base and docking, visit flags, infocard and every INI entry. With nothing selected it shows the system itself (music, background, ambient light…).
  • Status bar (bottom): what happened last, the cursor position in game metres, and how many items are selected. “All changes saved” in the top right turns into a list of unsaved files when you edit.

Moving around & selecting

Look aroundLeft-drag orbits, right- or middle-drag pans, the wheel zooms towards the cursor. Click the 3D view once, then fly with WASD (Q/E down/up, Shift faster).
Find somethingType part of a name or nickname in the Outliner, or search INI entries with key=value (for example loadout=li_). Double-click a row (or press F) to fly to it; Home frames the whole system. Ctrl+F searches all systems.
SelectClick in the 3D view or the Outliner. Shift/Ctrl+click adds to the selection; Ctrl+A selects everything visible; Edit → Select all of same archetype does what it says.
Move and rotateDrag the arrows (G) or rings (R) of the gizmo, or type numbers in Properties. Snap rounds to 100 m / 15° (change in Tools → Snap settings…). Y=0 puts the object on the system plane, where the navmap shows it.
Top viewT switches to a flat view from above — the same picture as the in-game navmap, with its grid letters and numbers if you turn on View → Navmap grid.

Showing what you need

A busy system like New York has over 500 objects and zones. Three tools keep the view readable.

What the 3D view draws: eyes and views

The Outliner on the left is also the switchboard for the 3D view. It works like layers in an image editor, on three levels, and every level has an eye:

KindObjects, Zones, Light sources.
CategoryObjects: Suns & planets, Stations & docking, Jump gates & holes, Trade lanes, Platforms & satellites, Other objects. Zones: Asteroid fields, Nebulae, Encounter zones, Patrol & trade paths, Exclusion zones, Death zones, Other zones.
ItemOne object, zone or light (a trade lane row counts as one item).

An item is drawn when its kind, its category and the item itself are all switched on. Kinds and categories apply in every system; item eyes are remembered per system. Nothing is ever written to the game files.

Eye (on hover)Drawn. Click to hide it.
Crossed-out eyeSwitched off at this level. Click to switch it on again.
Faded crossed-out eyeOn at this level, but a level above is off (e.g. the category). Click it to show only this one from that category — the category is switched on and its other items are hidden one by one.
Eye with a dotSwitched on, but some items inside are hidden one by one. Click to show them again.

Every eye says what it will do when you point at it. When anything is not drawn, a box at the top of the Outliner counts it, with Show all.

Shortcuts (as in Blender): H hides the selection, Shift+H hides everything except the selection, Alt+H shows everything again. A hidden zone or light that you select is still drawn so you can find it; a hidden object keeps its yellow selection box.

◎ Only listed (next to Objects / Zones / Lights) makes the 3D view draw only what the list shows. Combine it with the search box or the ⚙ filters: for one faction, open ⚙, pick the faction, then click ◎ Only listed.

Views

The View dropdown at the right end of the toolbar sets the kind and category eyes in one go (plus labels, paths and grids). Tick one view, or several to combine them — the combination shows everything any of the ticked views shows. Standard, Everything and Clean are single choices. Item eyes are not touched by views.

StandardThe default: everything except patrol paths, encounter zones and other zones, which clutter most systems.
EverythingEvery kind and category on.
Bases, lanes & jumpsSuns, planets, stations, trade lanes, gates and holes. No zones.
ZonesEvery zone category with labels, plus suns and planets to find your way.
Encounters & patrolsEncounter zones and patrol/trade paths, with the stations and gates they connect.
DefencesWeapons platforms, depots and the stations they guard.
Fields & hazardsAsteroid fields, nebulae, death and exclusion zones.
Clean (screenshots)Only models and the backdrop — no labels, zones, paths or grid.

When you click a category eye yourself, the toolbar shows Custom. Save current view… keeps the current eyes, labels and grids as a view of your own; Manage saved views… renames, updates or deletes them.

The View menu

Fine control over what is drawn: models, particle effects, 3D fields, planet rings, sun flares, paths, nebula fog, starsphere, grids and labels (L cycles important / all / none). View → Zone categories… picks which kinds of zone are shown.

Saving safely

  • Edits stay in the editor until you press Ctrl+S (File → Save all). Ctrl+Z / Ctrl+Y undo and redo everything, including wizards.
  • Before a file is written for the first time in a session, the original is copied to editor_backups\<session time> in the game folder; File → Backups… lists them.
  • File → Review changes… shows every file you changed compared with the original — INI files line by line with the section and nickname, DLLs by string and infocard. Restore original puts a single file back.
  • File → Snapshots (checkpoints)… keeps a named copy of everything you have changed so far (“before the Navy rework”). Restore makes your files match it again; a “Before restoring” snapshot is taken automatically, so even that can be undone.
  • Close Freelancer before saving — Windows locks files the game has open, and the editor tells you if that happens.

Walkthrough 1 · A new system

Goal: a new Liberty system with a sun, three planets, a station you can dock at, a jump gate to Colorado, a trade lane and NPC traffic.

  1. Open Create → New system wizard (complete system)….
  2. Name is what players see (“New Frontier”). Nickname is the region prefix plus the next free number; the wizard suggests one (Li06).
  3. Click the small universe map at the top right to place the system on the sector map.
  4. Template system decides the look and sound: music, background, dust, ambient light, space colour, local faction, and which sun and planet models are used. Pick a system that feels like the one you want.
  5. Choose the number of planets; 🎲 new layout rolls a different arrangement until you like the preview. Each planet gets a name and a death zone.
  6. Keep Station with base ticked, give the base a name and choose Copy base from: rooms, bar characters and markets are cloned from that base, so it works in game straight away.
  7. Under Jump 1 pick the system to connect to and gate or hole. Both ends are created, each facing the other system. Add up to three connections.
  8. Click Create system, look around, then press Ctrl+S to write all files.

Afterwards

  • Routes. The wizard extends the shortest-path files, so NPCs and the navmap can plot routes through the new system. Tools → Routes (shortest-path files)… checks them for every system and adds what is missing.
  • Check. Tools → Validate system lists problems in the open system; Pre-flight checks the whole mod.
  • Fine-tune. Everything the wizard made is ordinary objects and zones: move planets, add lanes (Create → Trade lane…) or draw zones (Z).

Walkthrough 2 · A base with a market

Goal: make the moon Maine in New York dockable, sell goods there, give it an infocard and fill its bar.

Make it a base

  1. Select Maine in the Outliner and open Create → Base for selected object….
  2. The Base nickname and strid_name are filled in for you (the name defaults to the object's own name).
  3. Choose a Template base. Its base INI, rooms, bar characters and market are copied — untick what you don't want.
  4. Click Create base. The object gets base and dock_with, and the base appears in universe.ini.

What the market sells

  • Select the object and click Market… in Properties.
  • Trade: sells means players can buy it here, buys only means the base only takes it. × price multiplies the goods.ini price; Price shows the result. Level and Rep lock items behind player level or reputation.
  • Type a good's name at the bottom and click + Add. Equipment and ships are in the Equipment & ships section below the commodities.
  • The Routes tab of the same window shows at once whether your prices create a good (or absurd) trade run.

Its infocard

  1. In Properties, next to ids_info, click ✎ to edit the text or + to create a new infocard.
  2. Type directly. Select text and use B / I / U, the font list and the colour swatches; Ctrl+B/I/U work too.
  3. Template… starts from a station or planet card (CLASS, GRAVITY, DOCKING…). Ctrl+Z brings your text back if you change your mind.
  4. ↔ game width narrows the editor to the in-game panel so you see where lines wrap. Apply stores it in the DLL; Ctrl+S writes the DLL file.

The bar

  • Base characters: the rooms of the base, the fixed NPCs (bartender, dealers) and every bar character with faction, voice, appearance and rumours. + New or Duplicate adds one.
  • News: the news items shown at this base, with the story progress that shows and hides them.
  • Tools → Base interiors… edits the rooms themselves (scenes, hotspots, fixtures) with a 3D view of the room.

Walkthrough 3 · A defence grid in bulk

Goal: hand all weapons platforms around a station to another faction, give them a heavier loadout, put them in a ring and number them neatly.

  1. Select the platforms: switch the View to Defences and Shift+click them, or select one and use Edit → Select all of same archetype.
  2. Shared entries lists every entry the selected items have. A value shown normally is the same on all of them; mixed · 3 values means they differ (hover to see the values), and 4/6 means only some have the entry.
  3. Type a new reputation (or use … to search factions) — it is set on all six at once. Do the same for loadout. × removes an entry from all; the row at the bottom adds a new entry to all.
  4. Move & arrange:
    • Offset moves the group by exact metres.
    • Rotate group turns the whole group around its centre — positions and orientations — by the angle you type, around Y (as seen on the navmap), X or Z.
    • Spread × pushes everything away from the centre (1.5) or pulls it in (0.5).
    • Distribute in a line spaces items evenly between the two farthest apart; Arrange in a circle… puts them on a ring of the radius you choose.
    • Same rotation copies the orientation of the item you selected last; Snap rounds positions to the snap step.
  5. Rename series: the editor guesses a pattern such as Li01_wplatform_{n:2} ({n:2} = 01, 02…). The line below shows the result before you click Rename. References in the system (docking, parents, trade lanes) and jump connections in other systems follow the new names; use References… for missions and other files.
  6. Every action is one undo step. Press Ctrl+S when you are happy.
If the selection mixes objects and zones, Keep only: at the top of the panel narrows it to one kind with a click.

Walkthrough 4 · A side mission

Goal: a job that starts when the player launches from Planet Manhattan — destroy three pirates near the California jump gate for 5,000 credits.

  1. Choose the Mission type: destroy a hostile group, escort a transport, patrol waypoints or courier a package.
  2. Pick the Start base; the job starts when the player has docked there and launches.
  3. Near object and the distance place the action; 🎲 tries another spot nearby.
  4. Choose the Hostile faction, the number of ships and their level. Ships come from that faction's random-mission ships for the level — the summary under the map names the ship it picked.
  5. Set the reward and check the three texts (start, active, success) the player will read.
  6. Install as: side job in a story mission runs alongside that story mission; replace a story mission slot makes this the whole mission (for example of a new game). Freelancer only runs the 14 story missions listed in Content.dll, so a new mission always lives in one of their files.
  7. Click Create mission, then Ctrl+S.

Fine-tune it in 3D

  • Every ship, formation, waypoint and trigger area of the mission file is listed on the left and drawn in the system. Select one and drag it with the gizmo, or click Place by click.
  • Tools → Mission scripts… shows the triggers, conditions and actions behind it if you want to go further.
  • To try it: start a new game (or load a save before that story mission), dock at the start base and launch.

Walkthrough 5 · Check and ship your mod

Pre-flight

  • Pre-flight reads every system, base, market, mission, ship, equipment entry and resource DLL and reports what would crash or misbehave: missing files, unknown nicknames, ids without text, duplicate nicknames.
  • errors can crash or break the game, warnings usually show up as something missing, notes are worth a look. Click an entry to see the INI lines; Export CSV for a list to work through.

See it in the game

  • Tools → Playtest here… (F5) writes a single-player save that starts in space next to the selected object, with the ship, money and rank you choose, and can start Freelancer. In the game: Load Game → the save whose name starts with “Playtest”.
  • The in-game test kit makes one small, visible change per editor at Planet Manhattan (name, texture, market, news, bar, room, cutscene) so you can confirm in a few minutes that everything the editor writes works in your copy of the game. A snapshot is taken first; Revert test kit undoes it exactly.

Package it

  1. Open File → Mods: export, install, conflicts…. Export my changes as a mod lists every file you changed or created, compared with the original backups.
  2. Fill in name, version, author and a short description; untick files that don't belong in the mod.
  3. Build mod .zip is for other editor users: they install it with Install a mod, which merges it with their own changes and shows conflicts side by side.
  4. Build player installer (.zip) is for players without the editor: they unpack it and double-click install.cmd. It checks the game version, backs up every file it replaces and stops cleanly if anything fails; uninstall.cmd puts the originals back.

Discovery & other big mods

Everything in this manual works on Discovery Freelancer as well. With a mod that size:

  • Map labels. “Sector” entries in universe.ini without a system file are only names on the navmap. They are greyed out in the Systems list and skipped by validation and the route tools.
  • Speed. Over 130 systems take a few seconds to load all at once; the trade planner works through more than two million runs in a few seconds and shows the best 300. Use view presets and eye buttons to keep busy systems readable.
  • Their conventions are kept. Discovery's market notation, NPC level names and infocard style are read and written the way the mod uses them, so your edits blend in.
  • Updates. Discovery updates replace its files. Switch on the update patch before you start editing, and your changes can be put back after every update.
  • Pre-flight also reports files the mod itself references but does not ship. Compare the list before and after your changes instead of trying to reach zero.

Keeping your changes across mod updates

A mod update — a new Discovery version, say — replaces the mod's files, and your edits in them are gone. The update patch keeps them safe. It is off until you switch it on.

  1. Open File → Mods: export, install, conflicts…, tab Update patch, and tick Keep an update patch of my changes.
  2. Work as usual. Every Ctrl+S also writes editor_patches\my-changes.flpatch.json in the game folder: not whole files but each change on its own — “Li01 · Li01_03 · reputation li_n_grp → li_p_grp”, a new object, a market price, an infocard text. The last ten versions are kept in editor_patches\history.
  3. Install the mod update as usual (the editor can stay closed).
  4. Start the editor. It notices that files with your changes were replaced and offers File → ⚠ Re-apply my changes after a mod update….
  5. The re-apply window sorts every change: apply (the update did not touch that spot), already there, decide (the update changed the same thing — you see what it was, what the update has, and yours; pick use mine or keep this version's), and cannot (for example a file the new version no longer has).
  6. Leave start a new baseline ticked: the old backups move to editor_backups_old, so Review changes, mod export and the next patch compare with the new version. Click Apply, look around, then Ctrl+S.
Download patch saves the patch as a file — to keep, or to apply to another installation with Re-apply a patch file…. Models, textures and other non-text files travel as whole files; INI files and the texts in resource DLLs travel change by change.

When something goes wrong

The game crashes after my changeTools → Crash & log analyser (FLSpew)… reads the game's log or a crash report and names the function that crashed and the kind of data it handles (loadouts, systems, effects…). Then File → Review changes… or a snapshot to go back.
A change doesn't show in the gameDid you save (Ctrl+S)? Bars and news are read when the game starts — restart Freelancer. Run Pre-flight for missing ids or nicknames.
“File is in use” when savingClose Freelancer (and FLServer) and save again.
A “3D view problem” message appears in the status barOne model or texture could not be drawn; the rest of the view keeps working. Hide that object with its eye button if it is in the way, and note the system and object when you report it.
The editor is slowTurn off View → Models or Particle effects while you edit layouts; use a view preset to draw less.
