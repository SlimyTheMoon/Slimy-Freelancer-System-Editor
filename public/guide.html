Freelancer System Editor — user guide

A local editor for Freelancer's game data: star systems in 3D, plus markets, bars, ships, effects, missions and save games. Every change is written into the game's own INI, UTF and DLL files, so the game picks it up directly.

Getting started

  1. Close Freelancer if it is running (Windows locks the resource DLLs while the game is open).
  2. Double-click start.bat in the system-editor folder. A console window opens and the editor opens in your browser at http://localhost:5717. Keep the console open while you work.
  3. The editor finds ..\Freelancer HD Edition on its own. For another install (for example a Discovery folder), choose File → Game folder… and click Browse… to pick it in a folder dialog (picking its DATA or EXE folder works too). In VS Code the choice is remembered in the extension's settings.
  4. The first system opens. Use the Systems tab on the left, the universe map, or Ctrl+F to move to another one.
Work on a copy of your install, or at least keep the automatic backups (see Saving). Chrome or Edge is recommended.

Eyes and views

What the 3D view draws is set in the Outliner on three levels, each with an eye: kind (Objects, Zones, Light sources), category (Suns & planets, Stations & docking, Jump gates & holes, Trade lanes, Platforms & satellites, Other objects; Asteroid fields, Nebulae, Encounter zones, Patrol & trade paths, Exclusion, Death, Other zones) and item. An item is drawn when all three are on. Kinds and categories apply in every system, item eyes per system; nothing is written to the INI. Crossed-out eye = off here; faded = a level above is off (click to show only this one); eye with a dot = some items inside hidden. H hides the selection, Shift+H everything else, Alt+H shows all. A selected hidden zone or light is still drawn; a selected hidden object keeps its selection box. ◎ Only listed draws only what the Outliner list shows (search, ⚙ filters) — e.g. one faction.

The View dropdown sets the kind and category eyes (and labels, paths, grids) in one go: Standard (default: no patrol paths, encounter or other zones), Everything, Bases, lanes & jumps, Zones, Encounters & patrols, Defences, Fields & hazards, Clean (screenshots). Tick several to combine them (union); Standard, Everything and Clean are single choices. Clicking a category eye by hand shows Custom. Save current view… stores the eyes and display switches as your own view; Manage saved views… renames, updates or deletes them. Views from older versions are converted (their object types become categories; faction rules are dropped — use ⚙ + Only listed).

Editing several items at once

With more than one item selected, Properties shows the bulk tools. Shared entries lists every entry of the selected items: a plain value is the same everywhere, mixed · N values differs (hover for the list), 4/6 means only some have it. Typing a value sets it on all; × removes the entry from all; the bottom row adds an entry to all. Move & arrange: exact offset; rotate the group around its centre (positions and orientations, around Y, X or Z); spread from or towards the centre; distribute evenly in a line between the two items farthest apart; arrange in a circle; all Y=0; same rotation as the last-selected item; snap positions. Rename series renumbers nicknames with a pattern such as Li01_wplatform_{n:2} (preview first); references in the system and jump connections in other systems follow. A mixed selection can be narrowed to one kind with Keep only. Every action is a single undo step.

Fields with … open a search picker (loadouts, factions, bases, stars, music, pilots, voices…). Fields with ✎ + ⌕ edit, create or pick an in-game text.

Saving, undo & backups

  • Edits stay in memory until you press Ctrl+S (also inside dialogs). That saves every changed file at once.
  • The first time a file is overwritten in a session, the original is copied to <game>\editor_backups\<session time>\. File → Backups… lists them.
  • Ctrl+Z / Ctrl+Y undo and redo across all files, including multi-file operations such as a jump connection. They also work while a dialog is open (markets, bars, ships, missions, strings…). The model, UTF and effect editors have their own undo for the file they have open. Undoing back to the saved state clears the "unsaved" mark.
  • File → Review changes… shows everything you changed before a playtest — see Review changes.
  • Lines you did not touch are written back byte-for-byte, comments included. Binary (BINI) files are saved as text INI, which Freelancer also reads.
  • Model, effect and DLL files are rewritten in their own format and checked before writing.

Snapshots

File → Snapshots (checkpoints)… keeps named copies of your work so you can try something risky and go back.

  • 📌 Take snapshot copies every file you have changed or added so far (Freelancer's untouched files are not copied, so snapshots are small). They are stored in <game>\editor_snapshots\.
  • Click a snapshot to compare it with your files now: what changed since, what was added or changed after it, what would be put back to the original.
  • Restore makes your files match the snapshot: its files are written back, files changed after it go back to the original, files added after it are removed. A "Before restoring …" snapshot is taken automatically first, so a restore can always be undone. The editor reloads afterwards.
  • Snapshots can be renamed (with a note) and deleted; deleting one never touches your current files.

Editing a system

Select and move

Click to select, Shift+click to add. G moves, R rotates, X switches between world and local space. Snapping is under Tools → Snap settings…. Exact values can be typed in the properties panel.

Add, copy, delete

Shift+A or right-click adds an object (pick the archetype with a 3D preview). Ctrl+C/V copy and paste, also into another system. Ctrl+D duplicates, Del deletes.

Rename

Renaming a nickname also fixes everything that points at it: prev_ring/next_ring, parent, field zones and the goto of jump gates in other systems.

System settings

Click empty space (or the system row in the outliner) for [SystemInfo], music, ambient colour, dust, the background starsphere and the system's universe.ini entry.

New system wizard

Create → New system wizard (complete system)… builds a whole, playable system in one go. On the right you see the universe map (click to place the new system) and a top-down preview of what will be created.

  • Name and nickname (region prefix + next free number, e.g. Li06); the name goes into an editable resource DLL.
  • Template system: music, background, dust, ambient light, space colour, local faction, the sun and the planet types are taken from it.
  • Planets (0–5) on orbits around the sun, named “Name I, II…”, each with a death zone; 🎲 rolls a new layout.
  • Station with base: a station next to the first planet with a base cloned from a template base — rooms, bar characters, news and markets (station bases of the template system are listed first).
  • Jump connections (up to three): gates or holes; both ends are created, each facing the other system, with the game's usual tunnel and effect.
  • Trade lanes from the station to each jump gate, and patrol paths station ↔ each jump with the population and encounters of a template patrol path (its [EncounterParameters] are copied too).
  • Routes: the three shortest-path files (systems_shortest_path.ini, shortest_legal_path.ini, shortest_illegal_path.ini) get routes to and from the new system (fewest jumps; legal = gates only). Existing routes are not changed.

Routes are found by travel time by default — flying at cruise speed (300 m/s), trade lanes at lane speed (2,500 m/s), 20 s per jump — or by fewest jumps.

The wizard opens the new system when it is done. Nothing is written until you press Ctrl+S; Ctrl+Z undoes it step by step. Take a snapshot first if you want a one-click way back, then run the pre-flight check before testing in the game.

Routes

Tools → Routes (shortest-path files)… checks systems_shortest_path.ini, shortest_legal_path.ini (jump gates only) and shortest_illegal_path.ini against your universe: systems without a section, reachable systems without a route, and routes that use a jump connection that no longer exists. Freelancer uses these routes for nav-map route plotting and NPC traffic.

  • Add missing / fix broken keeps every correct route and only adds or repairs; Rebuild all routes recomputes every line.
  • New routes are found by travel time (trade lanes count) or by fewest jumps. The original files were made by Digital Anvil with their own weighting, so a rebuild changes some vanilla routes — both kinds work in the game.
  • Story-only systems (visit = 128, St01–St03) have no routes in the original game and are left out unless you tick them. The original game also has no routes for Li05.

Step-by-step recipes

Add a dockable base to a planet or station

  1. Select the planet or station.
  2. Create → Base for selected object… Choose a template base (rooms, bar and market are cloned from it) and a nickname.
  3. Give the base a name with ✎ / + next to strid_name.
  4. Open Market… on the base to set what it sells, and Characters & news… for the bar.
  5. Ctrl+S.

Build a trade lane

  1. Select the two end objects (or nothing, and pick points).
  2. Create → Trade lane… Set the ring spacing and the template ring (its loadout and reputation are copied).
  3. Name the ends with tradelane_space_name — each ring names the end it leads to.

"Straighten & align" on an existing lane re-spaces and re-faces its rings.

Connect two systems

  1. Create → Jump gate / hole connection…
  2. Pick the other system and gate or hole. Both ends are created, facing each other's system on the universe map, with matching goto entries.

Create a new system

Create → New system… (or right-click the universe map). It adds the universe.ini entry, a name string and a system file from a template. Then connect it with a jump gate.

Zones, fields & nebulae

  • Z draws a zone by dragging on the map: sphere, ellipsoid, box, cylinder or ring, as plain, exclusion, death or encounter zone.
  • The zone panel edits shape, size, property_flags and visit with named flags.
  • Field file editor: a zone with an asteroid field or nebula shows its file below the zone: field, band, billboards, the asteroid cube, dynamic asteroids, exclusion zones, and for nebulae fog, exterior, clouds, lightning and puffs. The 3D view rebuilds as you type. A warning appears when several zones share one file.
  • Create → Asteroid field / nebula for selected zone… links a zone to an existing file or clones one.

Encounters & paths

The zone panel's Population section sets toughness, density, repop and relief times, and the encounter list: each encounter has an archetype, level, chance (0–1) and weighted factions. A missing [EncounterParameters] entry is added for you. "Copy to…" copies the whole block to other zones.

Patrol and trade paths are drawn as lines with arrows. Selecting a path segment shows its waypoint table: move, insert or delete waypoints, reverse, flatten, rename, set radius. Create → Patrol / trade path lets you click the waypoints in 3D (Shift+click snaps to objects, Enter finishes).

Suns, rings & lights

  • Suns are drawn as in the game: glow, centre, spines and lens flare, using the size limits recovered from Freelancer.exe. The star picker shows a live preview.
  • Planets edit their ring (ring = zone, file) and the ring file itself.
  • Lights show a falloff graph for attenuation or an atten_curve, with presets.

Names & infocards

Tools → Strings & infocards (Ctrl+I) searches every string and infocard in the resource DLLs. New texts get a free id. The DLLs are rebuilt on save (Freelancer must be closed).

Editing infocards

Infocards open in a visual editor that looks like the in-game infocard panel — type and format directly:

  • B / I / U (or Ctrl+B / I / U), alignment left / centre / right per paragraph, the font (the numbered fonts of DATA\FONTS\rich_fonts.ini; font 0 is the normal text), the colour (the game's default text colour, white, red, yellow, green, aqua, grey, purple or any colour), and ⌫ format to remove formatting.
  • Select text and press a button; with nothing selected, the style applies to what you type next. Enter starts a new paragraph; pasted text arrives without formatting.
  • Template… replaces the card with one of the usual layouts (station or planet card with CLASS / GRAVITY / DOCKING … lines, commodity, warning line); if the card has text you are asked first. Ctrl+Z / Ctrl+Y undo and redo everything in the editor — typing (word by word), formatting, alignment and templates. Escape or × with unsaved edits asks before discarding them. ↔ game width narrows the editor to about the in-game panel so you see where lines wrap.
  • Plain text mode edits without formatting (one line = one paragraph); XML mode shows the RDL markup with a preview.
  • Nothing is rewritten until you change something. Edits are written the way the game's own infocards are (<TRA bold="true"/>, <JUST loc="c"/>, color="#FF0000"…); all 5,258 original infocards survive the editor unchanged in content.

Markets & trade planner

Tools → Trade planner & markets (Ctrl+M):

  • Routes — every profitable commodity run, ranked by profit per minute over the real map (lanes, gates, cruise). Click one for the route.
  • Commodities — where each good is cheapest and where it sells best.
  • Markets — a base's commodities, equipment and ships with in-game names and prices. Change the price multiplier, "sells" / "buys only", level and reputation, add or remove lines.

Base characters & news

Tools → Base characters & news (Ctrl+B) edits mbases.ini and news.ini: rooms and fixtures, factions present and their missions, bar characters (looks, voice, rumours, bribes, information they sell) and news items with their story ranges and bases.

Ships, equipment & loadouts

Tools → Ships, equipment & loadouts…

  • Ships — every shiparch.ini entry with a 3D view of the model and its hardpoints. Hardpoint types are checked against the model's real hardpoints. The ship's price and package come from goods.ini.
  • Equipment — every item from the equipment files with its in-game name, price, and the ships that can mount it.
  • Loadouts — what NPC ships and stations carry: equipment per hardpoint and cargo. Duplicate a loadout to make a variant.

In-game test kit

Help → In-game test kit… checks that what the editor writes really works in Freelancer. Apply test kit takes a snapshot, then makes one small, obvious change per editor, all at Planet Manhattan, and saves:

  • a nav buoy “FL Editor Test Buoy” with its own info text near the Manhattan docking ring (system editor, resource DLLs);
  • a pink “FL TEST” checker texture on nav buoys (materials & textures);
  • one Manhattan commodity at three times its price (markets); a news story “FL EDITOR TEST: NEWS WORKS” (news, strings);
  • a different face for the Manhattan bartender (bar characters); the Rheinland bar music in the Manhattan bar (room INI); a wider bar camera saved as a text cutscene file (cutscene writer).

Close Freelancer before applying, then start it, begin a new game (it starts in the Manhattan bar) or load a save docked at Manhattan, and mark each item ✓ or ✗ with a note. The results are saved to editor_testkit_report.txt in your Freelancer folder. Revert test kit restores the snapshot, so every file is exactly as before.

Models & hardpoints

  • Assets → Model & hardpoint editor… (or "Hardpoints…" on an object): add (Shift+click on the model surface), move, rotate, rename and delete hardpoints; fixed or revolute with axis and limits.
  • Assets → UTF file browser… shows the node tree of any .cmp .3db .mat .txm .sph .ale file. Edit values, preview and replace textures (.dds/.tga), add or remove nodes.
Test an edited model in the game before making many more changes to it.

Materials & textures

Assets → Materials & textures… (or Materials… on an object) edits the material and texture libraries of a model: its own .cmp/.3db and its material_library files (.mat, .txm). Pick the file at the top left.

  • Materials: type (DcDt, DcDtOcOt, DcDtEt, EcEt…), diffuse/emissive/ambient colour, opacity and the texture of each slot (diffuse, emissive, detail). The preview shows the model with your unsaved changes, or the selected material on a sphere. New and Duplicate add materials; models refer to materials by name, so existing ones cannot be renamed.
  • Textures: thumbnail, size and format, which materials use it, Export PNG, Replace from image… and Add from image… (PNG, JPG, WebP, BMP or DDS). Images are resized to a power of two (up to 2048) and stored as DXT1, or DXT5 when they have transparency, with mipmaps. Transparency only shows with an …OcOt material type.
  • Undo/redo with the buttons or Ctrl+Z/Y; Save writes the changed files (originals backed up) and refreshes the main view.

Import & export models

Assets → Import model (glTF / GLB / OBJ)… turns a model from Blender or another 3D tool into a Freelancer .3db (one part) or .cmp (several parts) with its collision file .sur.

  1. Choose the model file together with everything it uses: the .bin of a .gltf, the .mtl of an .obj, and the texture images.
  2. Set the name, the folder under DATA, the scale (1 unit = 1 metre), whether the source is Z-up, and whether to keep the top-level nodes as separate parts.
  3. The preview on the right is the result loaded back through the editor's own Freelancer loader, with the collision hulls in green and hardpoints in yellow. Check it, then Write files (or Write + add solar archetype… to place it in a system right away).
  • Naming rules (common Freelancer modding conventions, so existing files work): name$lod1, $lod2… are extra levels of detail; name$hull is a collision hull; an empty named Hp… is a hardpoint (custom property hptype = rev makes it revolute); a node with the property construct = rev or pris (plus axis, min, max) becomes a moving part.
  • Without $hull nodes, a convex hull is made for each part. Textures are converted to DXT1/DXT5 DDS with mipmaps.
  • Assets → Export model to glTF (.glb)… writes any game model as a .glb with textures, parts, hardpoints (as empties) and collision hulls, which you can edit in Blender and import again. Only the highest level of detail is exported.

Animations

The model & hardpoint editor has an Animation & moving parts section for models that have them: docking rings, jump gates, station towers, base rooms, ship bay doors.

  • Pick an animation script (Sc_open dock a, Sc_rotate ring…), play it, loop it, change the speed or scrub with the slider.
  • Each moving part (revolute or prismatic joint) has a slider to pose it by hand within its limits. Posing does not change the file.

Cutscenes

Assets → Cutscenes (.thn player & script editor)… plays the game's .thn scripts — all 1,524 of the vanilla game — including base landing and launch scenes, bar scenes, the intro and the mission cutscenes.

  • The view goes through the cutscene's own cameras; switch to Free camera to look around, with cameras, markers and motion paths shown as helpers.
  • Base scripts are played together with their room: the room INI's set script and ambient scenes are loaded too (room checkbox), and the room's looping animation runs.
  • Played: cameras and camera changes, spatial and path animations, attachments (also to hardpoints), model animations (START_MOTION), light changes, particle effects and sounds and voice lines. Characters are shown as simple stand-in figures.
  • The Events tab lists every event — click one to jump there; Entities lists everything in the scene and shows models that could not be found.
  • The Script tab shows the script as text. Edit it and press Apply to see the result, then Save .thn. Freelancer reads text .thn files just like the compiled ones.

Editing a cutscene

  • Move things: in the free camera, click an object, character or marker (or pick it in Entities) and drag the gizmo — W move, E rotate. At 0 s this changes where it starts; at a later time it adds a key that moves it there in key length seconds.
  • 📷 Camera from view: fly the free camera to the shot you want, then press it — the selected camera (or the active one) takes that position, direction and field of view.
  • ✂ Cut to camera here switches to the selected camera at the current time.
  • Timeline: drag an event's bar to move it in time and its right end to change its duration (snaps to 0.05 s). Click a bar to select it; the Events tab then shows its time, duration, targets and values for editing, with Duplicate and Delete.
  • ↶ Undo steps back through your edits; Save .thn writes the script (as text; the original is backed up). Room scripts loaded alongside are shown faded and are not changed.

Characters

Characters are drawn with the game's own body, head and hand models (.dfm) from costumes.ini and bodyparts.ini, posed by their skeletons and animated with the body, face and hand animations (.anm, about 2,800 of them).

  • Assets → Characters & animations…: every costume in 3D; choose any animation of the right gender, loop it, filter by name.
  • In the bar editor, opening a character's Appearance shows that body, head, hands and accessory together.
  • Cutscenes and base interiors use the real characters; a stand-in figure appears only when a costume cannot be found.
  • As in the game, a character's height comes from its animation: the body stands at the floor height plus the animation's root height (≈ 0.96 m standing, ≈ 0.54 m sitting), so feet and seats line up. floor_height and START_FLR_HEIGHT_ANIM in cutscenes change the floor; moving a character up or down with the gizmo has no effect in the game either.
  • Animations blend: a new one fades in over 0.3 s on top of the running ones (immediately from the rest pose), timed ones fade out, and walking or turning animations move the character with their root motion.
  • Bar characters without their own fidget script get one from SCRIPTS\GCS\genericscripts.ini for their gender and their spot's posture (stand, sit), like the game does.

Base interiors

Tools → Base interiors… (or Interiors… on a base object) shows each room of a base in 3D, as the game builds it: the room's set script and ambient scenes, its looping animation, the fixtures (bartender, dealers) at their markers playing their fidget scripts, and the base's bar characters of that room on free seats and standing spots, up to the room's character density.

  • View through the room camera or any camera of the scripts, or fly around. Markers are shown as dots: orange for fixture spots (Zs/…), green for generic NPC spots (Zg/NPC/…), blue for the player. Click one to see its name.
  • Characters (mbases.ini [MRoom]): character density and the fixture lines — character, location marker, fidget script, type. Select a fixture's field, click a marker in the view and press Use to move it there.
  • Below: every section of the room INI — scripts, music and ambience (▶ plays them), camera, player placement, hotspots and ship placements — with add and remove.

Sounds & voices

Assets → Sounds & voices… plays everything under DATA\AUDIO.

  • Sounds: every [Sound] entry of the sound INIs with its file, attenuation and range.
  • Voices: each voice profile with its lines. The game stores each line in the voice's .utf bank under the CreateID hash of its name; recordings that no INI line names are listed by hash.
  • Find a voice line: type a line name to see which voice banks contain it.
  • Save any sound as .wav or as the .mp3 that is inside it.

Particle effects

Assets → Particle effects… asks for a [VisEffect] (engine glows, explosions, weapon effects…) and shows it live.

  • The left list is the effect's node tree: emitters create particles, appearances draw them; the arrows below show which feeds which.
  • Select a node to edit its values. Curves (size, alpha, colour over the particle's life; emitter values over time) show as a graph: drag the yellow points, or type in the table. + keyframe adds a point; the drop-down sets the easing.
  • sparam is the per-instance value the game passes in (e.g. engine throttle). Curves with several sparam items blend between them; the slider previews that. Many engine effects only emit at higher sparam, so move the slider if the preview stays empty. Fit frames the effect again.
  • The preview also shows beams (engine trails and similar ribbons), fields that push particles around (gravity, air, radial, turbulence, collide — their behaviour was read from the game's alchemy.dll), particle appearances that spawn other effects per particle and when particles die, and mesh appearances when the mesh name is an asteroid or solar archetype. Field behaviour (gravity, air, turbulence, radial, collide, dust) and the beam ribbons follow the game's alchemy.dll exactly.
  • Ctrl+Z/Y undo inside the dialog. Save .ale writes the file (original backed up). Value-only changes keep the rest of the file byte-identical.

Mission scripts

Tools → Mission scripts… opens the story missions (MISSIONS\Mxx\mxx.ini).

  • Triggers are drawn as a graph. A trigger waits for its one condition (Cnd_…) and then runs its actions (Act_…). Green lines: activates; red: deactivates; dashed blue: watches. A green bar marks triggers active when the mission starts.
  • Drag nodes to arrange them (kept per file), drag the background to pan, wheel to zoom, double-click to centre, Fit to see everything.
  • The right panel edits the selected trigger: condition, actions, "active at start", "repeatable". Names of other triggers and entities show as chips — click to jump there. "Referenced by" lists what switches this trigger on.
  • Entities lists ships, NPCs, objective lists, dialogs, objectives, formations, solars and loot, with which triggers use each.
  • Each condition and action shows its parameters as labelled fields (for example Act_SpawnShip: ship, objective list, position, orientation), with the type, default and what the game does with each value on hover. The descriptions were written from the game's own mission code.
  • The checks below the graph flag unknown references, triggers that are never activated, triggers without exactly one condition, and wrong parameter counts or words the game does not understand (which it silently replaces by a default). A few warnings exist in the original game data too.
Mission changes only show up in a new game or from a save made before the changed part. Keep a backup save.

New mission wizard

Tools → New mission wizard… writes a complete mission script from a template:

  • Destroy — fly to a marked spot near an object; a hostile group appears; destroy it. Escort — a friendly transport flies from the start base to a destination base and docks; optional ambush half way; the job fails if it is destroyed. Patrol — three waypoints, optional ambush at the second. Courier — fly to a base and dock.
  • Hostiles use the faction's random-mission ships for the chosen level (faction_prop.ini, npcships.ini), with its pilot voices and comm costumes; missing ship definitions are copied into the mission's npc_ship_file.
  • Objective texts, the title and the log entries become new strings; the reward is paid with Act_AdjAcct.

Where the mission runs. Freelancer only starts the 14 story missions listed in Content.dll (Mission_01a … Mission_13). So the wizard installs a mission either as a side job — its triggers are added to a story mission and start when the player has docked at the start base and launches again; it runs while that story mission is the active one and never changes the story mission's state — or by replacing a story slot, which makes the slot's file this mission alone (a new game lands at the start base with the ship, loadout and money you choose) for mods with their own campaign. Take a snapshot before replacing a slot.

After creating, the mission map opens on the new mission so you can move the spawn points and waypoints; Tools → Mission scripts… shows its triggers. Test in the game with a save from when the host mission is active.

Mission map (3D)

Tools → Mission map (3D)… (or 🗺 3D map in the mission script editor) shows where a mission happens, in the normal system view. A panel on the left lists, for the system you are in:

  • mission ships, formations and solars (their position), nav-map objectives (navmarker, rep_inst), trigger areas (Cnd_DistVec, random-pop spheres — drawn with their radius), player placements (Act_SetInitialPlayerPos, Act_MovePlayer), spawn/move positions (Act_SpawnShip, Act_SpawnFormation, Act_RelocateShip with coordinates) and waypoints (GotoVec). Arrows show orientations.
  • "Systems:" lists every system the mission uses — click one to go there. The coloured buttons hide or show a kind of marker.
  • Click a marker in the view or a line in the list to select it. Drag the gizmo to move it (W) or rotate it (E, where it has an orientation), type exact values, change a radius, or Place by click on the y = 0 plane. F flies to it.
  • Only the numbers on that INI line change; everything goes through the normal undo and Ctrl+S. Ships placed relative to another object (rel_pos) are listed with ◇ and can be given a fixed position.
  • A ? means the INI does not say which system the thing is in; the mission's main system is assumed.
  • 3D models (tick box at the top): mission ships, formations (each ship at its slot from formations.ini) and solars are drawn with their real models, turned the way they face — resolved through [MsnShip] NPC → [NPC] npc_ship_arch → [NPCShipArch] (the mission's own npc_ship_file, then npcships.ini) → shiparch.ini. The marker shrinks to a dot next to a model; F flies close enough to see it.

NPC ships

Tools → NPC ships… edits the [NPCShipArch] entries in MISSIONS\npcships.ini and in each mission's own npcships.ini. Each entry combines a ship (with a 3D view), loadout, difficulty level (d1–d19), pilot, AI state graph and npc_class tags (shown as removable chips). Unknown ships or loadouts are flagged. "Used by" lists the mission [NPC] sections that name the entry, and renaming updates them. In the mission script editor, an NPC entity has an NPC ship… button that opens its entry.

Review changes

File → Review changes… lists every file the editor has changed, compared with the file as it was before the editor first touched it (the oldest copy in editor_backups), plus unsaved edits.

  • INI files show a line diff with the section and nickname of each change.
  • Resource DLLs show which strings and infocards changed; model and effect files show which nodes changed.
  • Restore original puts a saved file back as it was (the current version is backed up first, so this can be undone the same way). An open system reloads automatically.
  • Copy summary copies a short list of changed files, e.g. for release notes.

Save games

Tools → Save game viewer… opens a .fl file from Documents\My Games\Freelancer\Accts\SinglePlayer. Encrypted saves are decoded automatically. It shows the pilot, location, ship, equipment, cargo, reputation and statistics with in-game names. You can change money, rank and reputation, then Download edited save and copy it over the original (keep a copy first). "Download decrypted .ini" gives a readable text version.

Balance tables

Tools → Balance tables… lists guns and launchers, shields, thrusters and ships side by side.

  • Derived numbers are computed exactly as the dealer infocard in the game computes them: hull and shield damage (munition plus explosion, shield damage including HULL_DAMAGE_FACTOR from constants.ini), range and speed (guided missiles included), refire, and thruster speed. Damage per second and damage per energy are added for comparison.
  • Blue columns are INI values: click a cell to edit it. The × button on a blue column header multiplies that value for every row currently shown, e.g. filter "liberty gun" and scale mun hull_damage by 1.1. Munition values are shared by every gun firing that munition, so each munition is changed only once.
  • Click a column header to sort, type in the filter to narrow the list, tick "with price only" to hide items that are not sold anywhere, and Copy as CSV for a spreadsheet. Everything goes through undo and Ctrl+S.

Mods: export, install, conflicts

File → Mods: export, install, conflicts…

  • Export my changes as a mod: every file the editor changed or created (compared with the oldest backup) goes into a .zip, with a manifest and the original version of each changed INI. The zip is downloaded and also saved to editor_exports. Anyone can install it by copying its DATA and EXE folders; with this editor they also get conflict checks and uninstall.
  • Install a mod: shows, per file, whether it is new, a clean replacement, or a conflict because your file differs from the one the mod was made from. Changed INI files are merged three-way when the mod contains their originals: your changes and the mod's are combined, and only lines changed by both are reported. Any plain mod zip with DATA\ / EXE\ folders can be installed too.
  • Installed mods & conflicts: every mod installed with the editor, which of its files were changed since, which files several mods change, and Uninstall, which puts back the files the install replaced and removes the ones it added.

Player installer

Build player installer (.zip) on the Export tab makes a package for players who do not have the editor. They unpack it and double-click a file — Windows' own PowerShell does the rest:

  • install.cmd finds the Freelancer folder (where the package was unpacked, the registry, the usual folders, or a folder dialog; a folder can also be dragged onto it), refuses while Freelancer or FLServer is running, shows what it will do, and warns when a file is not the one the mod was made for (another mod, a patch or a different Freelancer version) before replacing it. Every replaced file is backed up to <Freelancer>\mod_backups\<mod>\, every copy is checked, and a failure puts everything back.
  • uninstall.cmd restores every original and removes the files the mod added; files changed after the install are only overwritten if the player agrees. check.cmd only reports.
  • The package contains mod.json (name, version, author, description, a SHA-256 checksum of each file and of the original it replaces), the files under files\, the readable installer.ps1 and a README.

Tested with PowerShell 7 on every path (install, refusal of a second install, reinstall, uninstall, declined and accepted conflicts, failure halfway): the game folder ends up byte-for-byte as before. Players need Windows 10 or 11 (Windows PowerShell 5.1 is built in).

Server tools (multiplayer)

Tools → Server tools (multiplayer)…

  • Server: name, description and death penalty from freelancer.ini [Server]; what the server loads (dacomsrv.ini [Libraries] with FLHook / FLSharp, the FLHook plugins in EXE\plugins, [Initial MP DLLs]); ▶ Start FLServer (saves first if you want).
  • New players: the start options of the new-character screen (DATA\CHARACTERS\newcharacter.ini: reputation group, start base, ship package, pilot; packages with ship, loadout and money), each checked against the game data (⚠ = does not exist), and the starting reputations of new characters (EXE\mpnewcharacter.fl “house” lines) as sliders.
  • Multiplayer saves: the characters in My Games\Freelancer\Accts\MultiPlayer on this computer, opened in the save editor. Stop FLServer before changing one.
  • Server / client files: everything you changed, sorted by where it has to go — gameplay data must be identical on the server and every client; models, textures, sounds, interface, cutscenes and the name/infocard DLLs are only needed by clients; FLHook, its plugins and the new-character files only by the server — with a zip for each and a complete server and client package.

Pre-flight check

Tools → Pre-flight check (everything)… (also in the Playtest window) runs every check the editor has before you start the game:

  • all systems (the same checks as Validate all systems);
  • every file named in any INI (models, textures, material libraries, sounds, scripts) exists;
  • INI keys the game never reads, with the likely typo;
  • string and infocard ids that have no text, or point to a DLL that is not in [Resources];
  • goods, markets, loadouts and NPC ships that refer to things that do not exist.

Click an entry to see the INI lines around it, or to open the object in its system. The IDs & strings tab lists per resource DLL how many strings and infocards no INI uses, the next free id, and identical strings stored under several ids.

Patch manager

Assets → Patch manager (exe / dll hex edits)… applies community hex edits to Freelancer.exe, common.dll, server.dll and the other game files.

  • Every patch is checked byte for byte against your file: Apply appears only when the original bytes are there, Revert only when the patched bytes are. Anything else shows “does not match your file” and cannot be switched.
  • Value patches (cruise speed on the HUD, navmap limits, screen shake…) show the value in your file now; set a new one, or go back to the value of the reference install.
  • Each location shows the section, address and the function of the decompiled game it is in, with the C++ name where one exists, so you can see what code a patch changes.
  • Custom patch applies any other patch from a list: module, offset, original bytes, new bytes; it is applied only when the original bytes match.
  • Changes stay in memory until Write. Freelancer must be closed; the original files are copied to editor_backups on the first write.

How models are drawn

Materials are drawn with the render states of the game's own material types, taken from the decompiled Shading.dll and flmaterials.dll: lit or unlit, opaque, alpha-blended, additive or multiplied, two-sided or not. OcOt materials use alpha testing with 1-bit alpha (DXT1) textures and blending otherwise; detail maps are multiplied in at their tile rate; NullMaterial is not drawn. The [MaterialMap] of EXE\dacom.ini is applied the way the game applies it, for example detailmap_… materials become detail-map materials and …_glass becomes glass. An emissive colour (Ec) is part of the lighting that the texture is multiplied with, as in the game's fixed-function pipeline — so lit screens and signs show their texture instead of glowing white.

Faction relations

Tools → Faction relations… shows every rep line of initialworld.ini as a grid: the row is the faction that holds the opinion, the column the one it is about; red is hostile (≤ −0.6), grey neutral, green friendly (≥ 0.6). Pairs whose two directions differ by more than the threshold are outlined yellow; grey-blue cells have no line. Click a cell to change it with the slider or the quick values; edit both ways keeps the pair symmetric.

Translation

Tools → Translation: export / import texts… writes all strings and infocards of the chosen resource DLLs to a CSV file (UTF-8, opens in Excel or LibreOffice) with the columns id, dll, kind, source and translation. Fill in the translation column and import the file: the texts go into the same DLLs in one undoable step (save with Ctrl+S), so work on a copy of your install. Infocards stay RDL XML — translate the words between the tags.

References & rename everywhere

Edit → Find references / rename everywhere… (Ctrl+Shift+F, or References… on a selected object) searches every INI file of the mod — text and binary — for a nickname: where it is defined and every line that names it (loadouts, markets, encounters, missions, NPC ships, system files, universe.ini…). Click a hit to see its section; system hits can be opened directly.

Rename everywhere… changes the definition and every reference in one undoable step; Ctrl+S saves all touched files (originals backed up). Unsaved edits are included. Save games, file and folder names and DLL texts are not changed.

Playtest here

Tools → Playtest here… (F5) writes a single-player save that starts in the system you are editing — in space next to the selected object (or at the camera), facing it — and can start Freelancer.

  • Choose the ship (with its dealer package, any loadout, or the new-game starter equipment), money and rank, the respawn base, and whether the save is free roam (story finished, all gates unlocked) or the new-game story.
  • The save is built from the game's own new-game template (EXE\newplayer.fl) and written to Documents\My Games\Freelancer\Accts\SinglePlayer (an existing file of the same name is backed up). In the game: Load Game → “Playtest …”.
  • Write save & start Freelancer launches the game; when it closes with an error, the crash & log analyser opens with the game log.
  • Save your edits (Ctrl+S) first — the game only sees saved files.

Spawn simulator

Simulate spawns… in a zone's Population section (or Tools → Spawn simulator) runs thousands of spawns with the game's own encounter rules: encounter weights, the difficulty class added by the level, which factions can fly each formation, permutations, the NPC ship choice and group sizes.

  • Results: how often each encounter, faction and ship appears (with level and loadout), the most common groups, average group size and the spawn chance per check (density / repop_time).
  • Problems lists formations that can never spawn because none of the zone's factions has a fitting NPC ship — a common modding mistake that otherwise shows as an empty zone.
  • Not simulated: the player's reputation (hostile factions need the mission's hostile clamp in single player), density_restriction, relief_time and battle limits.

INI key reference

The editor carries a reference of every section and key the game reads, with type, default, allowed values and meaning, written from the reconstructed game source.

  • Hover a key name in the properties panel to see its description. Keys the game never reads are tagged unused (leftovers or typos — the game silently ignores them), and validation reports them as notes with a "did you mean …" suggestion.
  • The "+ add entry…" list also offers the other keys the game reads for that section.
  • In VS Code, hovering a key in any .ini shows the same description, and typing a key name offers the keys valid in that section.

Crash & log analyser

Tools → Crash & log analyser… explains what went wrong after a crash or a bad start.

  • Paste a crash dialog, Windows Event Viewer / error report text or a crash log, or press Load FLSpew.txt (the game's own log, written on every run) or Open file….
  • Crash addresses (e.g. common.dll+0x1a2b3, or "Faulting module name … Fault offset …") are turned into the function that crashed: about 28,000 functions from the decompilation, over 5,600 of them with their C++ name and source file. A hint says which kind of data that code handles (loadouts, systems, effects, missions, models…). If the crashing module is not a Freelancer file, a mod or plugin DLL is the cause.
  • Log lines are grouped and counted, linked to the code that printed them, and nicknames in them get a find button that searches all DATA INI files for that name.

Validation & tools

  • Tools → Validate system / Validate all systems: missing encounter parameters and factions, broken gotos, broken lane chains, duplicate nicknames, unknown archetypes, missing files and more. Click a finding to go there.
  • Tools → Hash tool: CreateID, faction hash, model CRC and ALE CRC for any name.
  • Tools → Rebuild [Archetype] preload list, Measure distance.

Then "Freelancer: Open System Editor" opens the editor in a tab; right-click a system .ini → "Open in Freelancer System Editor"; Ctrl+Alt+E jumps from the selection to its INI line; INIs edited in VS Code reload in the editor automatically.

Large mods (Discovery)

The editor works with vanilla Freelancer and with big mods such as Discovery Freelancer. Both have been tested with every tool. What differs on a mod:

  • Map labels. Discovery lists "sector" entries in universe.ini that have no system file; they only label the nav map. The Systems list shows them greyed out, they cannot be opened, and validation, pre-flight and the route tools skip them.
  • Markets. Discovery writes MarketGood = item, 0, 0, … for goods a base sells and …, 1, 1 for goods it only buys. The trade planner reads the 6th value (as Freelancer does), so routes work on both.
  • NPC levels. The mission wizard picks hostiles by level from both vanilla names (…_d3, …_d1-4) and Discovery names (…_d1_d4_…).
  • Infocards. Discovery's infocards use a different (numeric) RDL style. The visual editor keeps whichever style the card already has, so an edit changes only what you edited. New cards (and templates, plain-text edits and the test-kit card) are written in the style most of the mod's own cards use — for Discovery the numeric TRA data/mask form with its <?xml?> header; on vanilla nothing changes. The infocard editor's Notation list (Auto / Vanilla / Discovery) lets you choose explicitly; click the ⓘ next to it for a detailed comparison with examples.
  • Size. With ~130 systems, 2,500 trade nodes and over 2 million profitable runs, the trade planner takes a few seconds; the table shows the best 300 for the column you sort by. Pre-flight and the faction grid take 10–15 s.
  • Textures. Every texture kind Freelancer loads is decoded: DXT1/3/5, uncompressed DDS in 16/24/32-bit layouts, TGA of every type (colour-mapped, true-colour, greyscale, RLE), the early “Palette 8 bit” format, and DDS or TGA data stored under the “wrong” node name (Discovery has both). A texture whose data is empty shows its model untextured, and a problem in one object never stops the 3D view from drawing.
  • Pre-flight on Discovery reports some files the mod itself references but does not ship (old intro-system leftovers), and files that exist but are empty (0 bytes — Discovery ships a few placeholder models and effects). These are harmless to the game; check new ones only.
  • Memory. Models, textures and parsed files of systems you opened a while ago are released automatically (everything used by the open system and the one before stays), so a long session browsing many of Discovery's 133 systems keeps a steady memory use.

Update patch (mod updates)

File → Mods → Update patch (off by default). When switched on, every save writes editor_patches\my-changes.flpatch.json: your changes compared with the original files, one by one — INI changes per section and key (a section is recognised again by its name and nickname or other identifying key; repeated lines such as MarketGood by their first value), string and infocard texts per id, other files whole. Ten older versions are kept in editor_patches\history. At start-up the editor checks whether files of the patch were replaced outside it (a mod update); it then stops refreshing the patch and offers File → Re-apply my changes after a mod update…. Re-applying shows each change as apply, already there, decide (the new version changed the same thing: use mine / keep this version's) or cannot, and applies them as one undo step; Ctrl+S writes the files. “Start a new baseline” moves editor_backups to editor_backups_old\<date> (nothing is deleted) so later comparisons use the new version. Files are fine — rebuild the patch is for files you replaced yourself on purpose. Download patch / Re-apply a patch file… move a patch to another installation.

Troubleshooting

ProblemWhat to do
The editor feels slow or busyThe 3D view redraws at full speed only while you work in it; when nothing moves it drops to 5 frames a second, behind dialogs to one frame every 2 seconds, and it pauses while the editor reads many files (all systems, pre-flight, trade planner, opening a system). If it is still slow, close other GPU-heavy programs or switch off Asteroid fields & nebulae (3D) in the View menu.
Saving a DLL failsFreelancer is still running. Close it and press Ctrl+S again.

A change made outside the editor is not shownFile → Reload system from disk, or restart start.bat.
Names show as numbersA resource DLL listed in freelancer.ini is missing; the status bar says which.
Shortcuts do nothingClick the 3D view first; shortcuts are paused while typing in a field or while a dialog is open (Ctrl+S always works).
The page is blankCheck the console window for errors, then reload the page with Ctrl+F5.
